# Confluence 편집의 문맥 토큰 비교

2026-10-15, cfwiki 0.4.0과 실제 Confluence Cloud 테스트 공간에서 측정했습니다. 같은 합성 문서를 curl REST, 공식 Atlassian MCP v2, cfwiki로 읽고 한 문장을 수정한 뒤 독립 REST 조회로 결과를 확인했습니다. 원본 내용 보존을 통과한 경우에만 토큰 수를 비교합니다.

측정값은 **캡처한 입출력 텍스트를 실제 토크나이저로 센 토큰 수**입니다. 모델 API를 호출해 얻은 과금 사용량이 아닙니다. 숨은 추론, 시스템 프롬프트, 대화 이력 재전송, 캐시 할인, 도구 호출 포장과 클라이언트별 지침 주입은 포함하지 않습니다. 인증 헤더와 API 토큰은 모델 문맥·공개 결과에서 제외했습니다.

## 무엇을 바꿨나

- 다운로드는 `ID/문서명.md`, 자손은 부모 ID 폴더 아래에 저장합니다. 별도 Markdown 탐색 문서 대신 JSON manifest를 사용합니다.
- 기본 파일 YAML은 `type: Reference`, `status: current`, 중복 페이지 URL처럼 복원 가능한 값을 생략합니다. 사이트/API 바인딩, ID, 버전, 본문·storage 해시, 라벨, 사용자 메타데이터와 필요한 원본 XML은 유지합니다.
- 표·목록·코드·체크리스트·일반 링크와 이미지에는 Markdown을 사용합니다. 지원하는 패널·펼치기·인용은 `confluence-*` 펜스, 목차는 `confluence-toc` 펜스로 표현합니다.
- 알 수 없는 앱과 사용자 정의 네이티브 요소는 필요한 XML을 남깁니다. XML을 무조건 제거하는 `--preserve none`은 토큰 절감의 기본값으로 쓰지 않습니다.
- 스킬의 기본 읽기·편집 흐름과 기능별 참조를 나눠 관련 기능만 추가로 읽습니다.

## 측정 조건

공개 합성 corpus는 [token-corpus.mjs](https://github.com/TwoTwo-me/confluence-wiki-md/blob/main/benchmarks/token-corpus.mjs)에 있습니다. 한글 운영 문서, 표·코드·체크리스트, 패널·목차·접기·상태, 알 수 없는 앱 매크로, 링크·인용·중첩 목록, 긴 참조 문서의 여섯 종류입니다. 모든 방식은 별도 페이지를 만들어 같은 위치의 문장 하나를 바꿉니다. 준비용 페이지 생성은 읽기·수정 합계에서 제외합니다.

curl은 API 토큰을 인증 헤더로 보내 실제 GET/PUT을 수행합니다. 토큰은 비공개 프로필에서 읽어 curl의 표준입력 설정으로 전달하며 명령 인수나 결과 파일에 기록하지 않습니다. 원시 JSON, 필요한 필드만 남긴 응답, 로컬 파일에서 작은 치환을 수행하는 경우를 구분합니다.

공식 MCP는 `https://mcp.atlassian.com/v2/mcp`에 실제 JSON-RPC를 전송합니다. `getConfluenceContent(detail="full")`로 읽고 `snapshotToken`을 사용해 `updateConfluenceContent`를 호출합니다. Markdown 전체 교체, HTML 전체 교체, HTML 노드 부분 수정을 각각 측정합니다. 공간 지침과 공식 작성 안내를 먼저 읽으며 도구 스키마·초기 탐색·지침의 비용은 본문 작업과 별도로 기록합니다. 이 비용을 모든 클라이언트에 매번 부과되는 고정비로 보지는 않습니다. 클라이언트가 필요한 스키마만 로드할 수 있기 때문입니다.

cfwiki는 실제 CLI로 Markdown을 읽고, 전체 파일을 `upload`하거나 원본과 초안을 나눠 `apply --json`을 실행합니다. `apply`의 초안은 로컬 치환으로 작성하므로 전체 파일을 모델 출력으로 다시 생성하지 않습니다. 같은 전처리는 curl에서도 가능하며, 비교표에 해당 방식도 포함합니다. curl 로컬 패치에는 보조 코드의 구현·호출 셸 본문이 제외된 반면 cfwiki에는 실제 CLI의 절대 파일 경로를 포함한 명령 인수도 들어갑니다. 따라서 작은 고정비가 완전히 대칭인 벤치마크는 아닙니다.

`tiktoken==0.12.0`의 `o200k_base`와 `cl100k_base`를 사용합니다. 기본 표는 `o200k_base`이며 원시 집계 JSON에는 두 결과가 모두 있습니다. 특정 모델의 정확한 과금 토크나이저와 같다는 보장은 없습니다.

## 결과

읽기 요청·응답과 수정 입력·응답을 합한 토큰 수입니다. 준비용 생성·초기 스키마·지침은 아래 별도 항목에 있으며, 파일명과 해시·서버 응답을 포함한 실제 캡처값입니다. **cfwiki 행은 메타데이터를 포함한 `read` 결과**를 사용하므로 compact 다운로드 YAML의 절감률을 이 표에 추가 적용하지 않습니다.

| 문서 | curl 원시 JSON | curl 필터링 | MCP Markdown | MCP HTML | cfwiki upload |
| --- | ---: | ---: | ---: | ---: | ---: |
| 한글 운영 문서 | 4,029 | 2,323 | 2,320 | 3,975 | 3,548 |
| 표·코드·체크리스트 | 1,758 | 809 | 631 | 2,312 | 1,141 |
| 패널·목차·접기·상태 | 1,923 | 919 | 안전 거부 | 1,608 | 1,747 |
| 알 수 없는 앱 매크로 | 1,348 | 537 | 안전 거부 | 1,585 | 1,812 |
| 링크·인용·중첩 목록 | 1,277 | 487 | 642 | 1,625 | 1,188 |
| 긴 참조 문서 | 13,528 | 8,657 | 7,935 | 14,162 | 11,430 |

전체 본문을 다시 출력하지 않고 작은 치환이나 노드 수정만 보낼 때는 다음과 같습니다. curl의 로컬 패치는 별도 로컬 보조 코드를 사용하며, 그 코드를 처음 작성·설명하는 비용은 제외했습니다.

| 문서 | curl 필터링 + 로컬 패치 | MCP 노드 수정 | cfwiki apply |
| --- | ---: | ---: | ---: |
| 한글 운영 문서 | 1,211 | 2,218 | 1,457 |
| 표·코드·체크리스트 | 454 | 1,406 | 663 |
| 패널·목차·접기·상태 | 509 | 1,079 | 906 |
| 알 수 없는 앱 매크로 | 318 | 1,058 | 909 |
| 링크·인용·중첩 목록 | 293 | 1,080 | 671 |
| 긴 참조 문서 | 4,378 | 7,320 | 4,078 |

총 36개 방식·문서 조합 중 34개가 수정 저장과 내용 검사를 통과했습니다. 공식 MCP Markdown은 패널·목차 및 알 수 없는 앱 문서에서 `validation_failed`로 교체를 거부했고, 별도 REST 재조회로 원문이 유지됐음을 확인했습니다. 안전 거부를 완료된 수정이나 토큰 절감으로 합산하지 않았습니다.

긴 문서의 한 줄 수정은 curl 원시 JSON 13,528토큰, MCP 노드 수정 7,320토큰, cfwiki apply 4,078토큰이었습니다. cfwiki apply는 이 예에서 원시 curl보다 약 69.9% 적었습니다. 반면 짧은 문서에서는 필터링한 curl 로컬 패치가 더 적은 경우가 많았습니다. cfwiki upload가 모든 방식보다 작다는 결과도 아닙니다.

여섯 문서를 모두 완료한 방식의 합계는 curl 원시 23,863, curl 필터링 전체 교체 13,732, curl 필터링 로컬 패치 7,163, cfwiki upload 20,866, cfwiki apply 8,684, MCP HTML 25,267, MCP 노드 수정 14,161토큰입니다. cfwiki apply는 원시 curl 합계보다 약 63.6% 적었지만, 필터링한 curl 로컬 패치는 cfwiki apply보다도 적었습니다. MCP Markdown은 성공한 네 문서만 11,528토큰이므로 여섯 문서 합계와 직접 비교하지 않습니다.

MCP 세션에서 캡처한 전체 도구 스키마는 15,359토큰, 작성 안내 출력은 9,878토큰, 두 탐색 응답은 합계 5,279토큰이었습니다. 해당 세션에서 한 번 읽은 값이며 페이지별 표에 반복 가산하지 않았습니다. 스키마 지연 로딩과 캐시를 사용하는 실제 클라이언트의 비용은 달라집니다.

## 스킬과 YAML의 변화

스킬 진입 문서는 `v0.3.0`의 5,231토큰에서 1,138토큰으로 **78.25% 감소**했습니다 (`o200k_base`). 모든 상세 참조를 읽으면 그 내용도 문맥에 들어가므로, 모든 작업의 전체 사용량이 78% 줄었다는 뜻은 아닙니다. [스킬 측정값](benchmarks/skill-tokens-2026-10-15.json)

실제 한글 페이지 한 건에서는 전체 Markdown이 353→315토큰, YAML 부분은 250→212토큰이었습니다. 본문만 읽으면 101토큰이었습니다. 파일 편집에는 바인딩과 버전 정보가 필요하므로 `--body-only` 출력을 업데이트 파일로 사용하지 않습니다. [YAML 측정값](benchmarks/metadata-tokens-2026-10-15.json)

## 내용 보존 검사와 발견한 문제

원격 수정 후 독립 REST GET으로 보이는 텍스트, 코드, 표 셀 수, 링크, 작업 상태와 네이티브 매크로 정보를 비교했습니다. API의 정상적인 공백·코드 언어 별칭·파라미터 순서 정규화와 실제 내용 누락을 구분합니다. 노드 경계 변화와 패널 제목의 ADF 정규화를 허용하므로 추가 텍스트를 허용할 수 있으며, 강조·목록·제목 구조 전체의 동일성까지 검사하지 않습니다. 여기서 통과는 이 검사에서 내용 누락이나 수정 미반영을 발견하지 않았다는 뜻입니다. 이는 모든 화면 표현이나 외부 앱 동작의 완전한 동일성을 증명하는 검사는 아닙니다.

실험 중 cfwiki에서 문자 예제 `<example>`가 HTML로 해석되는 소실을 재현해, 일반 텍스트의 `<`와 엔티티처럼 보이는 `&`를 올바르게 이스케이프하도록 수정했습니다. 반복 왕복 테스트도 추가했습니다. 작업 안의 코드·이미지·링크, 이미지 제목, 대괄호 링크 라벨, 페이지 앵커와 교차 공간 동명 링크도 확인하고 수정했습니다.

기본 minimal 파일로 `apply`할 때는 검증한 과거·현재 storage에서 다시 구성 가능한 부분만 같은 표현으로 맞춥니다. 알 수 없는 XML이나 신뢰할 수 없는 초안 XML을 근거로 안전 검사를 생략하지 않습니다. 충돌·검증 거부·수정 미반영은 성공으로 계산하지 않습니다. 실제 Cloud가 새 code·목차·패널 매크로에 ID를 추가해 엄격한 저장 확인이 미확정으로 끝나는 문제도 발견했습니다. 이제 `apply`는 새 지원 매크로에 ID를 먼저 부여합니다. 원본 보존 XML이나 비교 검증을 완화하지 않고, 새 테스트 페이지 두 개에서 다시 확인했습니다. [추가 실사이트 확인](benchmarks/apply-confirmation-2026-10-15.json)

별도의 실제 트리 검사에서는 한글 제목과 3단계 계층, `index.md`·`log.md`, 링크 앵커, 첨부 바이트와 이름 유지, 최신 버전 충돌 거부를 확인했습니다. [실사이트 검증](benchmarks/page-tree-live-2026-10-15.json)

## 재현

재현용 하네스는 공개 GitHub 저장소에서 실행합니다. 설치용 런타임 패키지와 별개입니다. Node.js 24+, curl, Python과 `tiktoken==0.12.0`이 필요합니다. 비공개 REST 프로필, 별도의 공식 MCP V2 프로필과 테스트 공간의 부모 페이지를 준비합니다. MCP의 API 토큰 인증은 조직 관리자가 허용해야 하며, MCP용 앱 범위와 일반 REST용 범위는 별개입니다. [Atlassian 공식 인증 안내](https://developer.atlassian.com/cloud/rovo-mcp/guides/configuring-authentication-via-api-token/), [지원 도구](https://developer.atlassian.com/cloud/rovo-mcp/guides/supported-tools/)

```sh
git clone https://github.com/TwoTwo-me/confluence-wiki-md.git
cd confluence-wiki-md
PUPPETEER_SKIP_DOWNLOAD=true npm ci
python3 -m venv .venv-benchmark
.venv-benchmark/bin/pip install tiktoken==0.12.0
node checks/token-benchmark.mjs \
  --env /private/rest.env \
  --mcp-env /private/mcp.env \
  --parent CONFIRMED_TEST_PARENT_ID \
  --python .venv-benchmark/bin/python \
  --raw artifacts/token-benchmark/reproduction \
  --output docs/benchmarks/reproduction.json
```

이 명령은 지정한 테스트 부모 아래에 새 페이지들을 실제로 생성·수정합니다. 자격 증명과 원시 응답은 git에 넣지 마세요. 불확실하게 끝난 생성은 자동 재시도하지 않습니다. 실패 결과를 재실행할 때는 기록된 페이지 상태부터 확인하세요. 실험용 문서는 검증 근거로 남겼으며 기존 사용자 문서는 수정하지 않았습니다.

## 사용 권장 방식

읽기만 필요하면 `cfwiki read ID --body-only`로 필요한 본문을 확인합니다. 편집할 때는 최신 Markdown 파일과 별도 baseline을 보관하고 작은 diff를 만든 뒤 `apply --json`을 사용합니다. 여러 페이지 작업에는 ID 트리를 내려받고 필요한 문서만 읽습니다. 모든 XML이나 전체 파일을 매번 모델에 재출력하지 않는 것이 YAML 필드 몇 개를 줄이는 것보다 큰 차이를 만듭니다.

curl을 쓰더라도 인증과 storage 변환을 로컬 코드가 맡고 응답을 필터링하면 토큰을 줄일 수 있습니다. 공식 MCP의 부분 수정도 본문 전체를 재작성하지 않을 수 있습니다. 실제 절감은 문서 형식, 결과 보존 여부와 호스트 에이전트가 문맥을 구성하는 방법에 따라 달라집니다.
